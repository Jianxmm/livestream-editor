# 单人分享原声整理

把单一声学说话人的带时间码回放整理为按原顺序阅读的原声讲稿。只清理调试、口吃、机械重复和明确的 ASR 噪音；不改写成课程提纲、理论文章或运营文案。

## 输入与交付

在 `cases/YYYY-MM-DD-主题/` 下使用：

```text
inputs/
├── 01_直播回放.mp4  # 示例；工具保留实际媒体扩展名
├── 02_带时间码原稿.md
└── 03_人物与专名表.md
outputs/
├── 01_公众号可发布稿.md
├── 02_待核问题清单.md
├── 03_编辑质检报告.md
└── 04_整场音频.m4a
_work/
├── 场次分流.json
├── 整场音频.json
├── 完整编辑底稿.md
├── 内容覆盖表.md
├── 证据映射.json
└── 编辑决策台账.json
```

从 `assets/solo/` 创建对应文件。新任务先由 `主入口 SKILL.md` 生成 `_work/场次分流.json`；单人任务不生成或复制双人的说话人校准、时间轴和冲突清单。

`01_公众号可发布稿.md` 是为复用现有终审冻结脚本而保留的内部兼容文件名，不表示单人稿用于公众号。真人核验通过后，把发给学员的副本命名为 `01_学员学习分享稿.md`；不要在终审前改名或覆盖已冻结稿。

呈现标准参考人工学习稿：开头只保留主题、时间、地点、整场音频和正文入口；正文按原时间顺序分成自然章节，不加“讲者：”或姓名前缀，不显示AI状态、工具兼容说明、编辑说明或公众号运营信息。隐藏的正文审计标记可以保留。

真人继续修改过阅读副本时，以其明确确认的版本作为学习稿唯一正文来源。再次同步前先比较版本并回存案例，禁止用冻结的AI基线覆盖人工稿。学习侧派生物只做用户明确要求的机械转换；不要顺手补回讲者前缀、重写结尾或调整正文。

## 工作流

1. 读取 `主入口 SKILL.md` 生成的 `_work/场次分流.json`，必须为 `status=PASS`、`mode=solo`。验证原稿时间码严格递增、回放恰好一个内容说话人；平台多标签不推翻已核人数，原标签仍保留；直播间评论即使被讲者转述，也不新增说话人。
2. 建立人物与专名表。只把有清晰回听、正式物料或当事人依据的词标为“已确认”；上下文和机器转写不能关闭 P1。
3. 先通读全场，用现有覆盖表盘点主题、具体例子、推导、条件、步骤和互动，再按原时间顺序写 `_work/完整编辑底稿.md`。保留有效口述，删除调试、口吃与机械重复；ASR语义修复、专名/数字规范、隐私删改和内容移动写入台账。
4. 按真实主题形成阅读稿，完整长分享通常可用4–6章；不为章节数拆碎或重排内容。正文不使用逐段人名前缀；开头不写AI整理状态和说明性导语。正文保留原有效口述至少 70%，并保留有效完整底稿至少 90%；不增加 CTA、图片、二维码或额外身份信息。
5. 以每10分钟至少一行记录覆盖，建立至少6个真实证据模块，完成后从原稿反查去向。当前完整流程不适用于无法形成这些真实模块的短素材，应明确范围，不凑数。有效内容分母按 [content-scope.md](content-scope.md) 使用既有台账记录，不把已核无效调试或关播文字硬塞回正文。
6. 人名、数字、工具名、框架词及不能唯一听清的内容进入 P0/P1。未关闭 P1 时，正文删除疑词或使用不依赖疑词的保守表达。课程核心框架、口诀和步骤名要逐项核对名称、数量与顺序；不能因为转写错字，就整组换成泛称而丢失学习内容。名称未确认时保留已明确的逐项解释，将缺项集中交真人核实，不自行补字。

   结尾保留真实总结和感谢；只用于结束直播的设备确认、下播口令及转场指令不进学习正文。它们保留在底稿，并在覆盖记录中说明，不以此凑保留率。
7. 从原回放分离整场音频。新单人任务的音频不是可选项；脚本拒绝静默覆盖，并记录源/输出SHA-256及双方时长：

   ```bash
   python3 "<SKILL_ROOT>/scripts/extract_full_audio.py" \
     cases/YYYY-MM-DD-主题
   ```

8. 待核清单完成后先生成可点击原文索引，并提取疑点及随机抽听片段；即使无 P1，真人终审前仍需随机抽听：

   ```text
   python3 "<SKILL_ROOT>/scripts/livestream.py" source-index "<场次绝对路径>"
   python3 "<SKILL_ROOT>/scripts/livestream.py" review-clips "<场次绝对路径>"
   python3 "<SKILL_ROOT>/scripts/livestream.py" review-index "<场次绝对路径>"
   ```

9. 运行 `python3 "<SKILL_ROOT>/scripts/livestream.py" audit "<场次绝对路径>"`，清零 ERROR；待核清单变化后重建原文索引。以最终 `PACKAGE_AUDIT=PASS` 为准。

10. AI稿稳定且在人工作任何修改前，复用冻结脚本：

   ```bash
   python3 "<SKILL_ROOT>/scripts/track_human_review.py" freeze cases/YYYY-MM-DD-主题
   ```

11. 结果默认保存在本场 `outputs/`，不要求安装 Obsidian。需要阅读副本时按主入口使用导出工具，禁止覆盖人工修改。

12. 普通 Markdown 复制到目标编辑器会吞掉空段时，可另生成段间使用全角空格占位的 `.txt` 兼容版，标准 Markdown 保持不变。
13. 人工版的格式选择若与现有结构审计冲突，保留人工正文、冻结AI基线和原始失败输出到本场 `BLOCKED.md`。不得放宽审计，也不得为了变绿而改回真人已经删除的内容。

## 人工终审与学员发送边界

- 普通 `AUDIT=PASS` 只证明交付包、覆盖、证据和保留率通过机械检查。
- 未关闭 P1 必须有短音频或正文保守表达；P0 必须为 0。
- 真人逐条回听、随机抽听、独立通读并签名后，才运行 `--share`。
- 学员发送模式要求 P0/P1 全部关闭、评分性质为人工终审或独立双轨评审、真实终审人和日期、终审基线存在、学习稿独立通读为“真人已完成”。
- 单人学习稿不需要 CTA、图片、二维码或公众号运营信息；流程不自动发送，也不能把阅读副本误写成“已终审”或“可直接发送”。
- 统一入口的 `--release` 只用于双人，单人统一使用 `--share`。

## 交接记录的当前要求

按主入口的统一审计交接。高优先级问题逐条写明已回听、已当事人确认、已删除或已保守表达；含糊的“已解决”不作为发送或发布依据。保守表达在处理建议中引用正文实际采用的最终原句。问题内容或时间改变后，不能沿用另一问题的音频、核验内容或真人结论。终审表须有实际结论、真实姓名与有效日期；机器仍不能判断签字者是否真的听过，因此保留真人核对责任。
