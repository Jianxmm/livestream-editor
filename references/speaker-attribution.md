# 双人专访说话人校准规范

本包的实际工具入口见 [speaker-tools.md](speaker-tools.md)，默认使用已提供的本地声学后端，不要求购买云端转写服务。

这份规范解决的不是“这句话转写得准不准”，而是“这句话究竟是谁说的”。两者必须分开处理：

- **语音识别（ASR）**负责把声音转成文字。
- **说话人分离（diarization）**负责判断什么时候换了一个声音。
- **身份校准（identification）**负责把匿名声纹 `SPEAKER_00` 映射为真实姓名。
- **编辑归属**负责把最终正文署名建立在可追溯证据上。

通义或其他转写工具导出的“发言人1/发言人2”只是待验证标签，不是事实证据。上下文语义可以发现异常，但不能单独证明身份。

## 一、适用范围与输入等级

本规范仅适用于两位主要说话人的访谈。

| 输入等级 | 条件 | 可达到的状态 |
| --- | --- | --- |
| A | 两人分别录制、双声道或可独立分轨 | 最可靠；优先直接按物理音轨确定身份 |
| B | 单轨混音回放＋带时间码原稿 | 标准流程；必须做身份锚点、独立时间轴和冲突复核 |
| C | 只有带时间码原稿，没有回放 | 缺少本包必要输入，列明缺口，不能完成本包分流与编辑流程 |

如果转写平台能导出原始 JSON、SRT 或 VTT，必须保留原始结果，不要只保留整理后的 Markdown。原始时间戳、说话人标签和分句边界是后续比对依据。

## 二、正式编辑前的固定产物

有回放的任务在写完整编辑底稿前必须建立：

```text
_work/
├── 说话人校准.json
├── 说话人时间轴.json
└── 说话人冲突清单.md
```

三份文件的模板分别为：

- `assets/templates/08_说话人校准.json`
- `assets/templates/09_说话人时间轴.json`
- `assets/templates/10_说话人冲突清单.md`

它们不是终稿后的补充质检，而是生成终稿前的输入门禁。

## 三、身份锚点怎么建立

### 1. 每人至少两段干净样本

每位说话人至少选择两段身份明确的声音片段：

- 单段建议 10–30 秒；
- 每人累计不少于 30 秒；
- 不含另一人重叠讲话；
- 尽量没有音乐、掌声、外放回声或明显削波；
- 两段最好分布在直播不同位置，避免只采到开场时的一种声线。

### 2. 身份依据的可靠性顺序

从高到低使用：

1. 独立物理音轨；
2. 回放画面与口型明确对应；
3. 清晰自我介绍；
4. 对方点名后立即连续回应，且画面或声音切换可确认；
5. 已由真人听辨确认的稳定声纹。

“原转写写着发言人1”“这句话听起来像主持人”“从内容看应该是嘉宾”不能单独作为身份锚点。

### 3. 默认标签映射不是逐句结论

导入的字幕可能只有“发言人未标注”。此标签在 `source_label_default_map` 中必须为 `null`，不预设身份；仍需核验两位真人的声音锚点，并逐块依独立时间轴登记归属或冲突；单一干净声音可记录“声学归属”，不因原标签缺失制造每条字幕都要回听的伪冲突。模板会自动保留未知状态，不能为了运行工具补造两种原稿标签。

可以记录全场占多数的默认映射，例如“发言人1通常是主持人”。但任何一个原稿块仍要和独立时间轴对齐；默认映射不能覆盖局部串台。

## 四、独立全场说话人时间轴

时间轴应从回放音频独立生成，不读取原 Markdown 的说话人标签作为模型输入。实现工具可以替换，但输出格式固定。

时间轴包含两层：

1. `segments`：从声音得到的连续说话片段，保留匿名聚类、真实身份、起止时间和是否重叠。
2. `source_blocks`：原 Markdown 每个发言块与时间轴的逐块对齐结果。

允许的对齐状态：

- `一致`：默认标签、独立时间轴与身份锚点一致。
- `声学归属`：原标签未知且默认映射为null，但本场已核身份锚点、独立时间轴与当前三项哈希均对应，关联片段只有一位身份且无重叠、不确定或短片段；这是声音辅助归属，不是已完成人工终审。
- `真人已确认`：出现自动冲突，但已通过回放由真人确认。
- `冲突待核`：原标签和独立时间轴不一致。
- `混合说话人`：一个原稿块内实际包含两个人。
- `无法映射`：音频过短、过快、被遮挡或时间戳偏移，暂时无法稳定归属。

不同工具的分数不可直接横向比较，因此不强制虚构统一的“声纹置信度百分比”。系统只记录证据状态、冲突类型和是否由真人确认。

## 五、必须进入冲突清单的场景

以下情况一律不得静默自动修正：

- 原转写标签与独立时间轴不一致；
- 一个原稿块跨越两位说话人；
- 3 秒以内的短插话位于说话人切换附近；
- A—B—A 中间是极短句，前后两段语气与句法连续；
- 两人抢话、同时说话或后一句覆盖前一句；
- 主持人提问块中出现只有嘉宾才知道的年龄、地点、金额等短回答；
- 第一人称经历、称谓或自我指代与署名身份冲突；
- 时间戳偏移导致无法唯一对应；
- 独立时间轴没有覆盖原稿块。

语义规则只负责把问题送入冲突清单。最终身份以物理音轨、回放画面或真人回听为准。

## 六、快语速、抢话和混合发言怎么处理

1. **先判身份，再修文字。** 不要同时让一个模型在一遍处理中完成分离、认人、转写和润色。
2. 对问题点截取带上下文的短片段：通常保留问题点前后各 5–10 秒，而不是只听孤立的一句话。
3. 第二套 ASR 可以帮助判断文字，但不能替代身份确认；两个模型给出相同标签也不等于真人证据。
4. 一块里包含两个人时，必须拆成两个署名块；拆分点无法确认时标记 `混合说话人`，进入 P1。
5. 两人重叠且内容听不清时，只保留能明确辨认的部分。不能为了句子完整而补写被覆盖的内容。
6. 无信息量的“对、嗯、哈哈”可以在不影响下一句指代和现场反应时删除；承担立场、否定、情绪或转折作用的短插话必须保留。

## 七、放行规则

### 进入完整编辑底稿前

有回放时必须满足：

- 两位说话人的身份锚点均已确认；
- 每位至少两段样本、累计不少于 30 秒；
- 已生成独立全场时间轴；
- 原稿每个带时间码发言块在 `source_blocks` 中恰好有一条对齐记录；
- 所有不属于“一致/声学归属”的项都有唯一冲突编号，并出现在冲突清单；
- 冲突清单中的待核项同步进入 `outputs/02_待核问题清单.md`。

未满足时，不开始完整底稿和发布稿编辑。

### 普通审计

- 缺失说话人预检包：`ERROR`。
- 预检包结构无效、漏块、重复块或冲突未登记：`ERROR`。
- 仍有 `冲突待核/混合说话人/无法映射`：保留为 P1，稿件状态只能是“待人工终审”。

### 发布审计

- 正文采用的任何段落都不能建立在未关闭的说话人冲突上；
- “已解决”必须写明回放音频、回放画面、独立声纹窗口、真人回听或当事人确认中的至少一种可复核依据。“结合上下文”“按问答逻辑”只能触发复核，不得单独把状态改成“已解决”；
- 片段若从发布稿删除且署名结论不再影响任何对外文字，可标记“已删除”，但不得冒充已确认说话人；
- 冲突必须通过回放确认、当事人确认，或采用不依赖该归属的保守删除；
- 至少从全场五个时段随机抽查说话人归属；
- 已知说话人错误必须为 0。

## 八、长直播与工具选择

本包默认使用 [speaker-tools.md](speaker-tools.md) 的本地后端，分块处理长音频，再用同一组身份锚点跨块校准。原转写标签不作为声音模型输入。

有独立物理音轨时优先按音轨核实。已有第三方分离结果可以作为额外冲突线索，但更换后端仍需生成相同格式的材料并绑定本场输入哈希；跨段聚类编号不代表身份稳定。短句、打断、重叠讲话仍需回放确认，不能用模型投票代替。

## 九、成本控制

正常任务不要求真人从头重听整场。人工只集中处理：

- 每人两段身份锚点；
- 全部自动冲突；
- 所有混合发言和重叠讲话；
- 五段分层随机抽查；
- 正文中涉及标题、关键事实、医疗、收益和敏感表达的片段。

这样把人力用在系统最不可靠的位置，同时保留可追溯证据。
