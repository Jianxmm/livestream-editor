# 文稿整理

把视频、播客、直播和已有文字，整理成保留原意与重要细节的文稿；拿不准的人名、数字和表达单独列出来，方便核对。

你可以只给文字、只给音视频，也可以给指向单条内容的链接。普通内容按用途整理；要求直播标准时，保留原有的单人分享或双人访谈标准，交付**待发布文稿和待核对清单两份 Markdown**。

## 它可以帮你解决什么

| 你遇到的情况 | 可以帮你做什么 |
| --- | --- |
| 转写稿里口头词、重复和碎句太多 | 调整分段、标点和表达，保留观点、案例和重要细节 |
| 视频或播客只有声音，没有文稿 | 先使用可用字幕或转写工具取得文字，再整理 |
| 拿到一个视频或播客单集链接 | 尝试取得该条素材的字幕或音频，按你的需求处理 |
| 直播整理后像摘要，丢了问答和现场感 | 按直播标准保留分享推进、真实问答、追问和原话 |
| 人名、术语或数字可能转错 | 有依据时校正，不能确认的注明原文位置并列入待核清单 |
| 只想先了解内容，或者要保留逐字原话 | 按要求输出摘要、原始逐字稿或带时间标记的稿件 |

## 可以提供哪些材料

| 你手里有什么 | 怎样交给助手 | 需要知道什么 |
| --- | --- | --- |
| 文字或转写稿 | 粘贴文字，或提供可读取的 TXT、MD 等文件 | 可以直接整理；没有原声就不能回听确认 |
| SRT、VTT 或转写 JSON | 提供原始文件 | 助手先核对是否有完整正文及真实时间，不把摘要当原稿 |
| 本地视频或音频 | 上传文件或提供本机路径 | 优先使用已有字幕；没有文字时需要可用转写能力 |
| B站视频、小宇宙播客等单条链接 | 直接提供对应视频或单集链接 | 平台、登录状态和工具决定能否取得内容；不保证所有链接有效 |
| 回放和原始转写都有 | 两份一起提供 | 文字用于整理，回放用于定位和核对疑点，已有完整转写不重复重转 |

只提供一个合集或主页时，助手会先明确具体条目。Word、PDF、扫描件等能否提取出完整文字，取决于当前助手的文件读取工具；未取得正文时不会直接生成所谓完整稿。

## 第一次怎样安装

1. 点击上面的“下载统一版安装包”，解压后得到 `media-editor` 文件夹；安装整个文件夹，保留其中的隐藏文件和子目录。
2. 把文件夹交给支持 Skill 的 AI 助手，复制下面的话。
3. 安装后开启新对话，提供材料并说明你要什么。Codex 可用 `$media-editor` 调用；其他客户端使用其技能入口或直接说“用文稿整理处理”。

> 请读取这个文件夹的 README.md 和 SKILL.md，把“文稿整理”安装到当前助手实际使用的技能目录。先检查本次需要的能力；已有同名技能时保留旧版并说明差异，不要覆盖我的文件。

也可以在解压后的文件夹运行 `python3 install.py`。安装器默认使用 `~/.agents/skills/media-editor`，可用 `--target` 指定客户端实际的技能目录；已有同名目录时停止。使用命令不熟悉时，直接让助手完成即可。

如果通过 GitHub 仓库目录安装，统一版位于 [media-editor 子目录](https://github.com/Jianxmm/livestream-editor/tree/main/media-editor)，请让助手安装这个目录。仓库根部仍保留旧直播版的兼容文件。

WorkBuddy 的导入与真实处理效果尚未完成实机验收，不能据此说明已经兼容；后续会单独测试。

## 应该怎样选择输出

不用先选技术流程，直接说你想得到什么。未指定时，默认给完整整理稿和待核清单。

| 你的需求 | 可以这样说 | 最终得到什么 |
| --- | --- | --- |
| 完整整理稿，默认选择 | “整理成完整阅读稿，保留案例、数字和推理过程” | 整理稿＋待核问题清单，两个 Markdown 文件 |
| 按我们的直播标准整理 | “按直播标准整理，保留原话和真实问答” | 待发布文稿＋待核对清单，两个主要 Markdown 文件；另留内部质检材料 |
| 只要摘要 | “只要摘要，不需要完整长稿” | 摘要，保留改变结论含义的条件和限制 |
| 长稿前加摘要 | “给完整整理稿，并在前面加一段摘要” | 摘要＋完整稿及待核内容 |
| 原始逐字稿 | “只要原始逐字稿，保留原语言和发言顺序” | 原始或自动转写逐字稿，标明来源；不套用长稿删改规则 |
| 带时间标记的稿件 | “整理成带真实时间标记的稿件，方便回听” | 带时间标记的整理稿；没有可靠时间时会说明，不能推算 |
| 只获取素材 | “只获取这一条音频，不整理” | 在权限和工具允许时取得该条素材，并说明来源 |

明确同时要求“直播标准”和摘要等形式时，两份直播主稿仍然保留，其他形式作为补充。普通播客只要求保留顺序或对话，可以在普通整理中处理，不自动增加整套直播审核步骤。

## 按直播标准时，会多做哪些工作

先盘点全场内容，再整理底稿和阅读稿，最后从原稿反查遗漏；双人访谈保留主持人追问、双方观点归属和现场往返，单人分享保留讲述推进。专名、数字、疑难原词和说话人冲突按来源核查。

你主要收到**待发布文稿和待核对清单两份 Markdown**。必要的质检报告、底稿、原文对应和回听材料也会生成，作为核查依据。核心内部文件名中的“可发布”不代表已完成人工终审；仍需处理待核问题和人工审核。

完整直播标准目前支持单人分享及双人访谈。只有文字、回放无法读取或缺少实际声音核验依据时，助手会说明缺口，不能宣称已经完成原声核对。三人及以上不按这套完整直播标准宣称验收。

## 第一次使用可能遇到什么

- **只有文字，没有音视频工具**：普通文字可以直接整理，不需要先准备语音模型。
- **只有音视频，没有转写工具**：让助手列出缺项。包内提供可调用本机 `whisper-cli` 与已有模型的转写入口，也可以使用助手已有且获授权的转写服务；安装包不包含模型和账号。
- **链接打不开或需要登录**：使用你有权限访问的连接，或提供原文件；网站简介不能代替正文。
- **转写有错词或遗漏**：切分位置和较长无识别文字的时间会生成待核线索及短音频。空白可能是音乐或静音；机器候选不等于已经听清。
- **稿件有地方需要核对**：打开待核清单，根据原话位置和可用音频确认。无法确认的保持待核，不用上下文猜测冒充事实。
- **已经有人工修改稿**：告诉助手哪份是你确认的版本，继续处理前先比较，保留原始文件和旧版。

## 工具、费用与当前验证范围

Skill 需要 AI 助手执行，不能脱离助手单独生成文章。只有文字时主要依赖文件读写；音视频处理按需使用 FFmpeg、yt-dlp、转写工具和模型。云模型、转写服务或 AI 客户端可能按自身规则计费，首次下载模型也可能占用磁盘与时间；助手应按实际需求说明，不自动替你开通新服务。

本版已做本机独立安装、Codex 单一技能识别、公开音轨获取、本地转写和续用验证。**WorkBuddy、不同设备及真实长场文稿质量仍需实测**；机器检查通过不能代替原声核对或人工终审。具体见[验证情况](https://github.com/Jianxmm/livestream-editor/blob/main/media-editor/VALIDATION.md)。

更多工具操作见[素材获取与转写](https://github.com/Jianxmm/livestream-editor/blob/main/media-editor/references/acquisition.md)。本包独立实现，方法参考[音视频转录与长文整理](https://scys.com/skillhub/skills/skl_media-transcriber?from=copy_link&v=1.1.0)，不包含其源码或正文；内置直播核心采用其原有 MIT 许可，外部工具与模型的许可见[外部工具与许可](https://github.com/Jianxmm/livestream-editor/blob/main/media-editor/THIRD_PARTY.md)。
