# 文稿整理

根据用户的素材和用途，交付忠于来源的整理稿及待核问题。输入可以是视频、音频、字幕、逐字稿、其他原始文稿，或指向单条素材的链接。优先满足用户明确指定的输出、语言与详略；未指定时给完整中文整理稿和待核清单。原文件只读，不以简介或摘要充当逐字稿，不添加没有依据的事实。

## 确定路径

按以下顺序根据用户目标和内容选择，而非仅按平台名称：

1. **明确要求按直播标准**：始终执行下述直播核心，交付两份主要 Markdown；若还要摘要等，则作为额外产物，不替代两份主交付。
2. **明确只要求下载、原始逐字稿或摘要**，且未要求直播标准：即使素材本身是直播，也按要求处理；不要额外强制生成完整直播稿。
3. **其他直播回放、直播课程分享，或明确要求原声沉浸式直播级完整对谈**：读取 [内置直播整理核心](.livestream-core/SKILL.md) 并完整按其流程执行。B站等平台上的直播也适用。
4. **普通视频、播客、演讲、访谈及现有文字**：读取 [通用整理规则](references/general.md)。用户只要求保留原顺序、问答或现场语气时可在通用路径做到，不自动升级为直播全流程。有问答、分歧或多人观点时保留归属；不把三人以上内容冒充双人，也不承诺自动识别说话人。

走直播核心时，先按素材入口取得本地回放及带时间转写；没有转写就按授权转写，不能跳过核心输入要求。缺少回放、可信说话人数或其他必要证据时，按核心说明限制，不能改走通用流程假称同等验收。用户没有要求批量处理时只处理指定单条素材。

## 取得材料

先检查宿主能读取什么，使用已有完整转写或字幕；没有可用转写时，按需读取 [素材与转写](references/acquisition.md)。对于链接，保留实际来源，核对标题和内容；获取不了时说明平台返回的限制，让用户提供可访问链接或文件。不要绕过付费、验证码或访问限制。

原始媒体、原始字幕和转写只读；副本另存，来源、可用范围和时间信息如实记录。有字幕不能证明转写完整。使用本地转写时，读取生成的切点与时间覆盖核对材料：检查切点附近可能的丢字或错词，也检查未识别时间是否有语音。未实际回听的候选及对应时间放入待核清单；空白可能是静音或音乐，不能断定缺稿，也不能只因续跑成功就视为完整。通用路径只取得文字时可正常整理，但无法核对原声；明确要求直播标准时仍须满足直播核心的回放核验条件。有原声时对疑点优先定位回听。只能用 ASR 或上下文推测时标为候选，不能称作听清或事实确认。不存在的时间码、人物身份和来源不得推算或杜撰。

## 输出与恢复

通用整理默认交付 `01_整理稿.md` 和 `02_待核问题清单.md`，附可用来源和覆盖范围；用户指定摘要、时间稿、逐字稿等时遵从，不强加另一种体裁。内部记录源片段与整理段落的对应，便于反查；长材料覆盖前、中、后并检查分块边界。

**明确按直播标准的任务，两份主要交付均为 Markdown：**内核的 `outputs/01_公众号可发布稿.md`（单人模式按核心规则处理阅读副本文件名）和 `outputs/02_待核问题清单.md`。阅读稿是待审的待发布稿；无论名字是否包含“可发布”，有未核事项或未完成人工终审时不能声称已可发布。必要的 `03_编辑质检报告.md`、底稿、覆盖、证据、回听材料仍按核心生成并留作核查，不以省略质检换取两份交付。用户另要摘要等可单独附上，不代替这两份；输入或证据不足时如实说明缺口和已完成部分，不能伪造满足直播标准的成稿。

确认问题真实解决所需的音频、人工核验和权限按实际情况报告，不把格式或机器检查当作终审。

继续任务前先核对输入与已有结果，复用已完成部分，不覆盖人工稿或原文件。私有词库只在本机或用户授权的处理范围使用，不把其他资料中的事实移植进正文。涉及新的云服务、素材上传或费用时遵循用户授权和宿主规则，不把安装本 Skill 当作授权。不要自动发布或向他人发送。
